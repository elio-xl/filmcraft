# FilmCraft 基于 MCP 的自动剪辑需求文档

日期：2026-10-12  
版本：0.1  
状态：需求草案，供产品和开发评审

## 1 背景与目标

FilmCraft 需要让 Codex 等支持 MCP 的智能体完成素材浏览、片段筛选、时间线编辑、预览检查、保存和导出。用户用自然语言描述剪辑目标，智能体通过结构化接口操作编辑器，用户可以查看和继续编辑生成的工程。

素材理解采用渐进式流程：先提供图片缩略图和视频关键帧，再按需要提供更清晰的图片、连续帧或低清短视频。每份预览都保留与原始素材的对应关系，剪辑与最终导出使用原始素材。

目标是降低不必要的传输和分析开销，同时保证剪辑可定位、可验证、可恢复。缩略图不能承担的细节判断，应允许模型主动请求更多信息。

## 2 用户与典型场景

| 使用者 | 需求 | 成功结果 |
|---|---|---|
| 普通创作者 | 从图片和视频中制作指定主题、时长和画幅的短片 | 获得可继续编辑的工程和导出文件 |
| 专业剪辑者 | 让智能体筛选镜头、制作粗剪、添加标题和配乐 | 可查看选片依据、修改时间线、撤销错误编辑 |
| 自动化开发者 | 通过 MCP 或 CLI 批量完成可重复的剪辑流程 | 接口稳定、错误明确、结果可检查 |

典型指令：“从这些素材中选择适合旅行主题的镜头，剪成 30 秒横屏视频，加片头标题和指定配乐。”

系统需要支持以下过程：

1. 导入用户指定的素材，读取时长、尺寸、帧率和音轨等信息。
2. 请求素材缩略图和视频采样帧，建立初步内容理解。
3. 对候选片段请求更密集的帧，必要时读取低清短视频和转录。
4. 生成含素材 ID、源入出点、时间线位置和操作理由的剪辑方案。
5. 通过引擎命令执行编辑，读取时间线状态并查看结果。
6. 根据检查结果调整，保存工程并从原始素材导出。

## 3 现有能力与本次缺口

本节描述当前代码及文档中的能力，不代表已完成本次需求的运行验收。

| 能力 | 当前基础 | 本次需求 |
|---|---|---|
| MCP 接入 | 已有 stdio 服务，支持 Headless 和 Bridge | 延续现有协议及两种运行模式 |
| 命令执行 | 已有 `command_list`、`command_run`、`command_batch` | 补充素材分析入口及明确的结果契约 |
| 工程读取 | 已有 `project_inspect`、`sequence_inspect` | 提供素材分析所需的 ID、版本和时间映射 |
| 图片预览 | `render_preview` 和 `render_frame` 可按 `max_side` 返回时间线 PNG | 支持未加入时间线的素材及批量采样 |
| 代理媒体 | 已有低分辨率 H.264 和 ProRes 代理，导出使用原片 | 增加适合模型消费的短区间预览；低帧率分析副本不能直接当作现有剪辑代理挂载 |
| 转录 | 已有词级时间戳及文本剪辑命令 | 按素材读取并报告可用性；内置识别依赖可选功能和模型 |
| 镜头检测 | 已有针对时间线片段的场景切分检测 | 后续复用检测基础，提供不修改工程的素材镜头列表 |
| 恢复 | 编辑进入撤销历史；批量命令逐条执行 | 首版明确部分成功状态；后续增加适用编辑操作的事务能力 |

现有 `command_batch` 的每次编辑是独立撤销步骤。某一步失败不会自动回滚此前成功步骤，不得向用户或模型宣称批量操作具有原子性。

## 4 范围与优先级

### 4.1 P0 首版必须完成

- 按素材 ID 查询可分析状态和基本元数据。
- 返回静态图片缩略图，以及视频按时间区间均匀采样或按指定时间点提取的帧。
- 返回图片内容、实际源时间戳、尺寸和素材版本，支持模型直接查看。
- 支持对候选区间增加采样密度或提高分辨率。
- 为帧数、尺寸、响应字节数和后台任务设置上限。
- 保持分析请求不改变工程、播放头、选区和撤销历史。
- 复用现有命令完成剪辑、标题、配乐、工程保存和导出验证。
- 提供 Codex 接入说明及可重复执行的演示流程。

### 4.2 P1 后续增强

- 按源素材区间生成带音轨的低清短视频；不能消费视频时回退到连续帧。
- 返回带时间标注的镜头列表，结合镜头边界选择代表帧。
- 按素材区间读取转录和音频分析结果；提供可取消的长任务。
- 缓存素材分析摘要，支持按主题检索候选区间。
- 编辑方案预检、项目版本冲突检测、适用编辑操作的整体撤销及请求去重。

### 4.3 本次不包含

- 自研通用视觉大模型或视频理解模型。
- 强制依赖某一家模型服务或假定所有 MCP 客户端都支持视频输入。
- 公网 MCP 托管、多租户服务和账号计费系统。
- 自动发布到社交平台。
- 对任意素材和任意创作要求承诺无人检查即可直接交付。

## 5 素材理解要求

### 5.1 素材元数据

分析入口必须接受明确的素材 ID，不要求用户先把素材加入时间线。返回素材类型、可用状态、显示名称、尺寸、旋转信息，以及适用的时长、帧率和音轨信息。

素材离线、损坏或编码不支持时，返回原因和可执行的下一步。纯音频素材应报告其类型，图片请求返回不支持该操作，不能返回黑图伪装成成功。

元数据必须说明坐标系为源素材时间或时间线时间。子片段需要返回母素材 ID 和区间偏移；无法解析的引用应报错，不能猜测对应关系。

### 5.2 缩略图与采样帧

静态图片返回保持宽高比、处理显示方向后的缩略图；默认不裁掉画面内容。视频支持两种首版采样方式：

- 均匀采样：在指定区间内按最大帧数均匀取样，用于初步浏览。
- 指定时间点：按模型给出的源时间点取帧，用于局部观察和剪辑点检查。

每帧必须返回请求时间与实际解码帧的展示时间。帧应按实际时间排序；重复命中的帧需要去重并保留请求对应关系。短视频和静态画面不能通过重复返回同一帧凑满数量。

“均匀采样帧”和“检测到的镜头代表帧”必须有不同的采样策略标识。首版不能将均匀采样结果描述为完整镜头检测结果。

### 5.3 渐进式观察

模型首先请求少量低分辨率图片；发现候选镜头或信息不足后，再请求具体区间。响应应告知采样范围、数量、是否受预算限制，以及继续获取内容的方法。

针对文字、小物体、快速动作或剪辑点，允许提高分辨率及采样密度。不能因缩略图中未出现某个事件，就断言原视频不存在该事件。

### 5.4 低清短视频

P1 按指定区间生成分析预览，返回源素材起点、持续时长、输出帧率、音轨状态、文件大小及可访问资源。

预览时间与原片时间必须可换算。降帧率只减少采样，不能改变播放速度或造成音画不同步。此类分析预览独立于要求匹配原片帧率的现有剪辑代理。

只有客户端和模型的实际调用链经过验证支持视频内容时，才能将视频作为模型输入。返回本地路径、资源链接或 MP4 文件本身，不等于模型已读取其中内容。能力未知时使用图片帧回退。

### 5.5 音频与转录

P0 不强制安装语音识别模型。已有转录可供剪辑流程复用；无识别能力时明确报告缺失，并允许使用外部提供的转录。

P1 提供带源时间戳的词句、语言、可用的说话人标签及置信信息。静音区间、音乐节奏和响度应通过相应音频分析能力得到，不能从静态图片推断。

### 5.6 原片时间映射

- 内部编辑运算继续使用 `filmcraft_time::Tick`，每秒 254016000000 ticks。
- 新增接口中的精确 tick 值使用十进制字符串传输，避免客户端浮点数精度损失；不改变现有接口格式。
- 区间使用左闭右开语义 `[start, end)`，校验起止顺序和素材边界。
- 变帧率素材依据实际展示时间定位，不通过“帧号除以名义帧率”猜测时间。
- 时间线变速、倒放和重复使用同一素材时，明确返回源时间与时间线时间的映射。
- 模型选择近似剪辑点后，引擎按目标序列帧边界执行，并返回实际采用的边界。

## 6 MCP 接口要求

以下名称为拟议名称，用于明确职责；最终注册名称由接口实现评审确定。新增工具必须复用引擎能力，CLI、控制通道和 MCP 的相同操作应具有一致语义。

| 拟议工具 | 阶段 | 主要输入 | 主要输出 |
|---|---|---|---|
| `media_inspect` | P0 | 素材 ID | 元数据、版本、可用分析能力 |
| `media_frames` | P0 | 素材 ID、区间或时间点、采样策略、尺寸、预算 | 图片内容、逐帧时间映射、分页或预算状态 |
| `media_preview_clip` | P1 | 素材 ID、源区间、尺寸、帧率、音轨选项 | 任务 ID 或预览资源及时间映射 |
| `media_shots` | P1 | 素材 ID、源区间、检测参数 | 镜头起止时间、代表帧及检测状态 |
| `media_transcript` | P1 | 素材 ID、源区间 | 转录内容或明确的不可用原因 |

### 6.1 图片响应

`media_frames` 必须通过 MCP 图片内容块返回实际可查看的图片，同时返回结构化元数据。图片块与元数据通过稳定的帧 ID 或内容序号对应，不能只返回模型无法访问的本地文件路径。

逐帧元数据至少包含：素材 ID、素材版本、帧 ID、请求时间、实际源时间、图片尺寸、MIME 类型及采样策略。批量结果包含成功条目和失败条目，不能静默丢弃失败。

没有任何可用帧时返回工具错误。部分成功时明确标记部分成功，并为每个失败条目提供原因。

### 6.2 能力与兼容性

服务端暴露构建支持的解码、导出、转录和分析能力。客户端能否把图像、视频或音频交给模型，由接入配置和实际兼容性验证决定，不能仅由 MCP 连接成功推定。

保留现有工具和参数的兼容性。新增接口应有机器可读参数 schema、默认值、上限、错误说明及工具注解。只读分析可以生成可丢弃缓存，但不能改变工程状态。

首版支持 Headless 和 Bridge。Bridge 中的素材分析应直接调用引擎读取源素材，避免通过临时插入片段或切换用户播放头实现。

### 6.3 长任务和错误

长时间解码、转码或分析必须进入后台任务，提供进度、查询和取消能力；执行期间仍能读取工程状态。取消应清理任务产生的不完整缓存，不删除原片或其他任务的结果。

错误至少区分：参数不合法、素材不存在、素材离线、编码不支持、解码失败、预算超限、能力不可用、任务取消、磁盘空间不足和版本冲突。错误信息包含相关素材或任务 ID，以及可采取的恢复方式。

## 7 默认预算与缓存

下表是首版拟定的产品默认值和上限，不是已经测得的性能指标。实现可以配置更小的限制；改变硬上限需要同步接口文档和测试。

| 项目 | 默认值 | 上限或处理方式 |
|---|---|---|
| 单次图片长边 | 512 像素 | 1920 像素；保持宽高比，不主动放大小图 |
| 单次视频采样帧数 | 8 帧 | 16 帧；更多内容分次请求 |
| 单次素材范围 | 一个素材或一个源区间 | 多素材由客户端有界调度 |
| 单次图片响应 | 按所选尺寸和帧数计算 | 8 MiB，包含 base64 和元数据；超限明确返回预算状态 |
| 低清视频区间 | P1 默认 10 秒 | 单次最长 30 秒 |
| 低清视频规格 | P1 默认长边 960 像素、最高 12 fps | 保持原速，低帧率原片不补帧；单文件上限 24 MiB |
| 分析任务并发 | 单会话 1 个活动解码或转码任务 | 队列最多 8 个，超限返回繁忙错误 |

响应超限时返回完整可解析的受限结果及继续请求方式，不能截断 JSON 或图片字节。资源上限应在分配内存和启动任务前尽量校验，不能先生成任意大的结果再拒绝。

缓存键包含素材内容版本、源区间、采样策略、尺寸、编码参数和生成器版本。原片被替换后旧缓存必须失效；同名路径不能直接视作同一内容。支持主动清理缓存，并避免清理正在使用的结果。

图片压缩体积下降不等于模型 token 消耗同比下降。首版记录帧数、尺寸、响应字节数、处理时间和缓存命中情况；模型调用成本由客户端按实际模型统计。

## 8 编辑执行与恢复

智能体生成的剪辑方案应包含素材 ID、源入出点、目标轨道、时间线位置和操作理由。所有工程修改通过现有命令系统执行，优先显式指定目标，不依赖当前 UI 选区。

P0 使用现有撤销及批量结果机制。批量失败时返回成功步骤、失败步骤及结果，客户端重新读取工程状态后决定恢复或继续，不能盲目重放整批命令。

P1 对可撤销的工程编辑提供方案预检、版本检查、整体提交和整体撤销。导出、上传、覆盖外部文件等具有外部副作用的操作不纳入可回滚编辑事务。

素材分析完成后，如果素材版本已变化，旧分析结果不能直接用于执行。用户在 Bridge 模式中修改项目时，后续操作应重新读取相关状态；P1 的原子版本检查进一步防止并发覆盖。

## 9 工程与数据约束

- 遵守仓库的 Never crash 规则：不合法参数、损坏媒体、超大尺寸、溢出、磁盘写入失败必须返回可处理错误，工程和会话继续可用。
- 后台任务使用仓库要求的 panic 防护，并在失败时结束任务状态，不能永久显示运行中。
- 保持纯 Rust、依赖分层和开源许可证约束；产品不链接、捆绑或依赖外部 FFmpeg 执行分析。
- 验收媒体使用原创生成素材或许可合规的测试素材；不提交大体积二进制夹具，不使用 Adobe 资产。
- 首版沿用本地 stdio 和本地 Bridge。由客户端将请求到的预览送入模型上下文，FilmCraft 服务端不自动上传完整素材到其他服务。
- 日志记录工具、素材 ID、参数摘要、耗时和错误，不记录图片 base64、完整音视频或完整转录正文。
- 源媒体保持不变；分析缓存可清理，最终导出从原片读取。

## 10 验收标准

| 编号 | 场景 | 通过条件 |
|---|---|---|
| AC01 | 图片素材不在时间线中 | 可按素材 ID 获取方向正确、比例正确的缩略图，工程状态不变 |
| AC02 | 视频均匀采样 | 返回预算内的有效帧，逐帧包含实际源时间，图片与元数据一一对应 |
| AC03 | 指定时间点和局部加密 | 请求区间可被进一步细分，实际返回帧的时间映射可核对，剪辑点能定位到原片 |
| AC04 | MCP 模型实际看图 | 在目标 Codex 客户端中，模型可区分测试帧中的明确场景变化；仅收到路径不算通过 |
| AC05 | 分析操作只读 | Headless 和 Bridge 中，工程内容、播放头、选区和撤销历史在请求前后一致 |
| AC06 | 预算和错误输入 | 负时间、越界区间、零帧数、超大尺寸、异常数值、损坏媒体均返回错误或明确受限结果；后续正常请求仍成功 |
| AC07 | 取消和任务失败 | 可查询并取消长任务，取消后无持续运行的作业，原片及工程不受损 |
| AC08 | 缓存失效 | 相同内容及参数可复用缓存；替换原片后不会返回旧图，旧版本结果不能误用于执行 |
| AC09 | 完整剪辑流程 | 导入至少三段生成视频、一张图片和一段生成音频，截取拼接、添加标题和配乐、预览、保存、重新打开并导出成功 |
| AC10 | 原片导出 | 分析使用低分辨率帧时，最终输出仍采用指定导出尺寸及原片内容，无误用缩略图造成的画质替换 |
| AC11 | 部分失败恢复 | 批量编辑中注入失败，返回的成功与失败步骤和实际工程一致，已成功编辑可通过现有撤销机制恢复 |
| AC12 | P1 视频兼容回退 | 支持视频的接入可分析短片；不支持或能力未知的接入得到连续帧，不出现“文件已返回但模型没有画面”的假成功 |

AC01 至 AC11 是 P0 发布门槛，AC12 随 P1 视频能力交付。精确时间测试覆盖分数帧率、变帧率、子片段偏移及时间线变速映射；不支持的输入必须明确报错。

自动化测试使用可预测的场景切换、帧编号和音频时间标记检查映射及输出。真实模型参与的兼容性验证独立记录客户端版本、模型、输入内容和结果，不能用模拟模型测试替代。

性能验收记录固定测试素材和硬件上的首帧耗时、批量耗时、峰值内存、响应大小及缓存命中耗时。首版不承诺未经基准测试的固定秒级响应，但所有请求必须受资源预算和取消机制约束。

## 11 交付与实施顺序

1. **素材读取闭环**：新增素材元数据及抽帧入口，完成精确时间映射、预算和异常参数测试。
2. **MCP 看图闭环**：返回真实图片内容，接入 Codex，验证按需查看详细帧及两种运行模式。
3. **剪辑交付闭环**：通过现有命令完成 AC09 场景，保存可编辑工程和导出结果，验证撤销及部分失败恢复。
4. **低清视频与音频增强**：交付 P1 短视频、转录读取及镜头列表，验证能力回退。
5. **执行可靠性增强**：交付方案预检、版本冲突检查、编辑事务和请求去重。

P0 交付包含新增接口、参数文档、Codex 配置示例、生成式测试素材说明、自动化测试和端到端验证记录。代码合并前执行仓库要求的 `cargo xtask ci` 质量门禁。
